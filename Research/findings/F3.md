# F3 — Hermes Agent architecture and Workers compatibility

Research date/access date: 2026-09-22

## Findings

### 1. Hermes Agent is a Python-based, host-oriented agent runtime.

- Claim: Hermes Agent is the Nous Research self-improving agent with a CLI, TUI, gateway, tools, skills, memory, scheduling, and messaging surfaces.
- Evidence: The official README describes the agent, its learning loop, terminal interface, Telegram and other messaging gateways, scheduled automations, and delegation.
- URL: https://raw.githubusercontent.com/NousResearch/hermes-agent/main/README.md
- Source date: repository content accessed 2026-09-22
- Confidence: high

### 2. Hermes requires a conventional Python/Node toolchain.

- Claim: The installer provisions Python 3.11, Node.js, ripgrep, ffmpeg, and a portable Git Bash where needed; the project requires Python >=3.11 and <3.14.
- Evidence: The README describes the installer and Termux/Windows setup; `pyproject.toml` declares the Python version constraint.
- URLs:
  - https://raw.githubusercontent.com/NousResearch/hermes-agent/main/README.md
  - https://raw.githubusercontent.com/NousResearch/hermes-agent/main/pyproject.toml
- Source date: repository content accessed 2026-09-22
- Confidence: high

### 3. Telegram is a first-class Hermes messaging gateway, but not a Workers handler.

- Claim: Hermes supports Telegram through its messaging gateway and includes the `python-telegram-bot[webhooks]` dependency in its messaging extra.
- Evidence: The README lists Telegram among messaging platforms and describes `hermes gateway setup` plus `hermes gateway start`; `pyproject.toml` lists the Telegram webhook dependency.
- URLs:
  - https://raw.githubusercontent.com/NousResearch/hermes-agent/main/README.md
  - https://raw.githubusercontent.com/NousResearch/hermes-agent/main/pyproject.toml
- Source date: repository content accessed 2026-09-22
- Confidence: high

### 4. Hermes supports serverless-ish backends, but the documented targets are not Cloudflare Workers.

- Claim: Hermes lists local, Docker, SSH, Singularity, Modal, Daytona, and Vercel Sandbox terminal backends; the README specifically positions a cloud VM or serverless infrastructure as the host for the agent.
- Evidence: The README's feature table lists these backends and says the agent can run on a $5 VPS, GPU cluster, or serverless infrastructure.
- URL: https://raw.githubusercontent.com/NousResearch/hermes-agent/main/README.md
- Source date: repository content accessed 2026-09-22
- Confidence: high

### 5. The dependency and tooling surface is too large for direct Workers execution.

- Claim: Hermes' core and optional dependencies include Python packages for HTTP, FastAPI, Uvicorn, browser/websocket functionality, document extraction, voice, and platform-specific process management; this is not a Worker-compatible bundle.
- Evidence: `pyproject.toml` lists the core and optional dependencies and platform markers.
- URL: https://raw.githubusercontent.com/NousResearch/hermes-agent/main/pyproject.toml
- Source date: repository content accessed 2026-09-22
- Confidence: high

## Architecture implications

- Run Hermes on a VPS, container, Modal/Daytona/Vercel Sandbox, or another supported host.
- Use Cloudflare Workers as a Telegram webhook gateway, durable queue producer, stream proxy, or session-state service if edge ingress is useful.
- A Workers-to-Hermes integration should use an authenticated HTTP/RPC boundary and an idempotency key per Telegram update.

## Open questions

- No official Cloudflare Workers deployment target for the full Hermes runtime was found in the reviewed primary documentation.
- A minimal Hermes-compatible protocol could be implemented separately, but that would be a custom harness rather than Hermes itself.
