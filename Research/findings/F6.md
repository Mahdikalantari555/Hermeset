# F6 — Lightweight custom harnesses and NanoClaw-like designs

Research date/access date: 2026-09-22

## Findings

### 1. NanoClaw is the closest reviewed lightweight OpenClaw alternative, but it still needs a host and containers.

- Claim: NanoClaw describes itself as a lightweight, understandable alternative to OpenClaw with one host process, per-agent containers, memory, scheduled jobs, and Telegram support.
- Evidence: The NanoClaw README describes container isolation, multi-channel messaging, scheduled tasks, memory, and customization by code changes.
- URL: https://raw.githubusercontent.com/nanocoai/nanoclaw/main/README.md
- Source date: repository content accessed 2026-09-22
- Confidence: high

### 2. NanoClaw is not directly deployable as a Cloudflare Worker.

- Claim: NanoClaw requires Node.js 22+, pnpm 10+, and Docker; its architecture uses a host process, per-session SQLite files, and agent-runner containers.
- Evidence: The README lists Node/pnpm/Docker requirements; the package manifest declares Node >=22 and dependencies including `better-sqlite3`; the architecture document describes host/container SQLite mailboxes.
- URLs:
  - https://raw.githubusercontent.com/nanocoai/nanoclaw/main/README.md
  - https://raw.githubusercontent.com/nanocoai/nanoclaw/main/package.json
  - https://raw.githubusercontent.com/nanocoai/nanoclaw/main/docs/architecture.md
- Source date: repositories accessed 2026-09-22
- Confidence: high

### 3. NanoClaw's architecture is a useful blueprint for a custom Workers-first harness.

- Claim: The host-router → durable inbox → agent runner → durable outbox → delivery pattern is a strong design for a custom agent, even if NanoClaw itself runs outside Workers.
- Evidence: NanoClaw's architecture document describes platform events entering a host router, host writes to `inbound.db`, the agent runner processing messages, and the host delivering `outbound.db` responses.
- URL: https://raw.githubusercontent.com/nanocoai/nanoclaw/main/docs/architecture.md
- Source date: repository content accessed 2026-09-22
- Confidence: high

### 4. A custom Workers harness should intentionally omit host-only capabilities.

- Claim: A Workers-native harness can support model calls, deterministic HTTP tools, D1/Durable Object state, scheduled jobs, and Telegram delivery, but should delegate shell commands, browser automation, arbitrary filesystem access, and long-lived local processes to an external sandbox or agent host.
- Evidence: Workers limits bound CPU/memory and do not provide a normal host filesystem or arbitrary process manager; Cloudflare recommends Queues/Workflows for work that exceeds `waitUntil()`.
- URLs:
  - https://developers.cloudflare.com/workers/platform/limits/
  - https://developers.cloudflare.com/workers/runtime-apis/context/
- Source dates: 2026-09-05 and 2026-09-10
- Confidence: high

### 5. A minimal custom harness can be much smaller than OpenClaw/Hermes/NanoClaw.

- Claim: The smallest useful design is a Telegram webhook Worker, a model adapter, a deterministic tool registry, D1 or Durable Object session storage, and a Queue/Workflow for long jobs.
- Evidence: Public Workers Telegram examples show that the ingress and model-call path can be implemented in a single Worker; Cloudflare's storage, Queue, Workflow, and Workers AI primitives cover the remaining platform needs.
- URLs:
  - https://raw.githubusercontent.com/tbxark/ChatGPT-Telegram-Workers/master/README.md

  - https://developers.cloudflare.com/workflows/
  - https://developers.cloudflare.com/durable-objects/
- Source date: sources accessed 2026-09-22

## Recommended custom harness shape

- `telegram-ingress` Worker: webhook validation, update normalization, idempotency, Queue enqueue, quick 200.
- `agent-core` Worker: one bounded model/tool loop using an OpenAI-compatible provider such as Kilo API; no Workers AI model is required.
- `session-store`: D1 for durable conversation/tool state; Durable Object per chat if serialization and low-latency coordination matter.
- `jobs`: Queues for retries and background work; Workflows for multi-step approval or long-running tasks.
- `model`: external OpenAI-compatible API configured with `OPENAI_BASE_URL`, a Worker secret API key, and a selected model. Use chat-completions or responses-style tool calling according to the provider's supported endpoint.
- `tools`: HTTP APIs and Cloudflare bindings inside Workers; GitHub Actions or another external sandbox for shell/browser/filesystem tools.

## GitHub Actions as an auxiliary executor

- GitHub Actions is useful for delayed, heavy, scheduled, or high-trust tool execution: repository operations, code execution, browser automation, long-running data processing, periodic memory compaction, backups, and GitHub memory exports.
- It is not a good interactive Telegram agent core. A workflow has runner startup and queue latency, is event/schedule oriented, and is not a low-latency request/response runtime.
- Public repositories can use standard GitHub-hosted runners without consuming the account's private-repository minute allowance; GitHub Free private repositories include 2,000 Linux minutes per month, 500 MB artifact storage, and 10 GB cache per repository.
- `GITHUB_TOKEN` is limited to 1,000 requests per hour per repository; authenticated personal access tokens and GitHub App installation tokens are generally limited to 5,000 requests per hour. GitHub also enforces secondary rate limits and content-creation limits.
- A Worker can trigger a workflow through a repository dispatch or workflow dispatch, passing a small job ID and allowlisted parameters. The workflow should read the real job from D1 or another durable store, not trust a large Telegram payload.
- Use one concurrency group per chat or per job, idempotency keys, least-privilege permissions, pinned action versions, and a separate token with only the scopes needed for the auxiliary tool.
- Recommended boundary: Workers handles Telegram, memory, orchestration, and fast HTTP tools; Actions handles optional heavy tools and maintenance jobs; the external OpenAI-compatible API handles model intelligence.
