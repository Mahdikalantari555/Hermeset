# F2 — OpenClaw architecture and Workers compatibility

Research date/access date: 2026-09-22

## Findings

### 1. OpenClaw is a host-oriented multi-channel gateway, not a Worker bundle.

- Claim: OpenClaw runs a Gateway on a user's device or server and connects messaging channels, tools, skills, plugins, and model providers.
- Evidence: The official README describes OpenClaw as an assistant running on your own computer, with one Gateway controlling channels and state/memory/credentials living on the user's hardware.
- URL: https://raw.githubusercontent.com/openclaw/openclaw/main/README.md
- Source date: repository content accessed 2026-09-22
- Confidence: high

### 2. The runtime requirements are incompatible with a normal Cloudflare Worker.

- Claim: OpenClaw expects a supported Node.js runtime, currently Node 24.16+ or Node 26.1+, and ships a large compiled distribution with host-oriented components such as process execution, SQLite, sandboxing, native hooks, and channel adapters.
- Evidence: The README gives Node version requirements; the package manifest lists a large `dist/` tree and host/runtime components including process, SQLite, sandbox, native hook, and channel modules.
- URLs:
  - https://raw.githubusercontent.com/openclaw/openclaw/main/README.md
  - https://raw.githubusercontent.com/openclaw/openclaw/main/package.json
- Source date: package version 2026.9.5, accessed 2026-09-22
- Confidence: high

### 3. OpenClaw already has production Telegram support, but it is implemented in the Gateway.

- Claim: OpenClaw's Telegram channel is production-ready for DMs and groups via grammY; long polling is the default and webhook mode is optional.
- Evidence: The official Telegram documentation describes production readiness, pairing, group support, and transport modes.
- URL: https://raw.githubusercontent.com/openclaw/openclaw/main/docs/channels/telegram.md
- Source date: repository content accessed 2026-09-22
- Confidence: high

### 4. OpenClaw's webhook design uses durable admission before acknowledging Telegram.

- Claim: In webhook mode, OpenClaw validates the request guard, Telegram secret token, and JSON body, then commits the update to a durable ingress queue before returning an empty 200. Slow agent turns do not hold Telegram's delivery acknowledgement.
- Evidence: The Telegram transports documentation describes the acknowledgement boundary and durable queue behavior.
- URL: https://raw.githubusercontent.com/openclaw/openclaw/main/docs/channels/telegram/transports.md
- Source date: repository content accessed 2026-09-22
- Confidence: high

### 5. OpenClaw's Gateway is a long-lived local service with a WebSocket control plane.

- Claim: One long-lived Gateway owns messaging surfaces; control-plane clients connect over WebSocket, and the default bind host is loopback. Remote access is recommended through Tailscale, VPN, or an SSH tunnel.
- Evidence: The architecture documentation describes the Gateway, WebSocket protocol, default port, and remote access guidance.
- URL: https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/architecture.md
- Source date: repository content accessed 2026-09-22
- Confidence: high

### 6. OpenClaw can use Cloudflare AI as a model provider without running OpenClaw on Workers.

- Claim: The package distribution includes a Cloudflare AI Gateway extension, which indicates provider integration, not Workers runtime compatibility.
- Evidence: The package manifest lists `extensions/cloudflare-ai-gateway/**` among packaged extensions.
- URL: https://raw.githubusercontent.com/openclaw/openclaw/main/package.json
- Source date: package version 2026.9.5, accessed 2026-09-22
- Confidence: medium

## Architecture implications

- Do not try to deploy the full OpenClaw Gateway as a Cloudflare Worker.
- Use OpenClaw on a conventional host, container, VPS, or supported serverless backend, and let Workers act as the Telegram ingress/orchestration edge if desired.
- If OpenClaw itself terminates Telegram, Cloudflare Workers is unnecessary for the bot transport; Workers may still sit in front as a reverse proxy or durability layer, but that adds complexity.

## Open questions

- The public documentation reviewed does not show an official Cloudflare Workers deployment target for the full OpenClaw Gateway.
- A custom subset of OpenClaw's protocol could be reimplemented in Workers, but that would no longer be running OpenClaw itself.
